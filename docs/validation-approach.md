# Validation Approach — Simulated Study (Not Real-World Testing)

## Decision

The original project plan (see `docs/testing-protocol.md`) called for real
testing with at least 3 new testers or re-engaged original users. That real
testing was **not performed**. Instead, this project uses a **simulated
validation study**: hypothetical tester personas and synthetic interaction
data, generated by a documented script, to demonstrate the validation
methodology and what analysis of real results would look like.

**This is explicitly not a substitute for real-world validation.** No claim
in this repository or report should be read as evidence that real people
found the prototype useful, clear, or trustworthy. It demonstrates that the
prototype can be evaluated using this methodology, and shows the kind of
findings that methodology would surface — nothing more.

> **Academic note:** the assignment brief's stated requirement was 3+ real
> testers or re-engagement with original users. Whether a clearly-labelled
> simulated study satisfies that requirement is a judgement call for the
> course rubric/faculty — this decision should be confirmed with the course
> instructor/coordinator before final submission if there is any doubt.

## Why simulate rather than skip validation entirely

Skipping validation entirely would leave the "Validate" stage of
Ideate → Prototype → Validate → Deliver empty. A simulated study instead:

- Exercises the full testing protocol end-to-end (tasks, measures,
  analysis) against realistic-but-hypothetical inputs.
- Produces a genuine, reproducible analysis pipeline (`src/simulate_validation.py`
  → `data/simulated_validation_data.csv` → the summary in
  `docs/simulated-validation-study.md`) that could be pointed at real data
  later with no changes to the analysis code.
- Surfaces the same category of usability questions (clarity, trust,
  willingness to use) that real testing would ask, which is useful for
  identifying prototype weaknesses even without real users.

## How the simulation was built (full transparency)

`src/simulate_validation.py` defines 5 hypothetical personas, each with a
short description and a set of **bias values** (typical 1–5 ratings) that
the persona would plausibly give. Actual simulated ratings are drawn from a
random distribution centred on each bias value (seeded, reproducible), not
chosen by hand after the fact. The generation logic, including the bias
values themselves, is visible in the script — nothing is hidden.

## What this does NOT show

- It does not show that real customers at the Gandhipuram shop (or anywhere)
  would respond this way.
- It does not validate the Gradient Boosting model's real-world accuracy
  (see `docs/methodology.md` for that distinction).
- The "findings" below are a demonstration of analysis method, not empirical
  results about human behaviour.

## If real testing becomes possible later

`docs/testing-protocol.md` retains the original tester instructions, tasks,
questions, and a blank measurement sheet, so real testing can be run and
incorporated at any point without redesigning the study.
